Requires: [ ChallengeSolved ]` and describes "two independent requirers" as if both were capability-declared. `GridMapRom.Requires` is actually `Array.Empty<Capability>()` — win-line rules match `IChallengeSolved` directly via NRules polymorphic matching, not capability declaration; only `Loot` actually declares the `Requires` entry. Ticket [0052](../ClaudeWiki/Processes/Handoffs/0052-implement-loot-rom-content-expansion-spec-md.md)'s Response already caught and documented this exact discrepancy (traced back to `grid-rom-d20-split-spec.md`'s original capability table, a Phase 2.7 artifact, not something this phase introduced) — but the spec file's own Capability-declarations section still reads as if it were true. Doc-currency item for whoever maintains `loot-rom-content-expansion-spec.md` (Juno/Amara); doesn't affect behavior, already tracked in 0052's ticket history, not filing a duplicate.
