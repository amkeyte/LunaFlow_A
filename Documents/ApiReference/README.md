# LunaFlow API Reference

**GENERATED — do not hand-edit; regenerated on every `dotnet build` from XML doc comments.**

This is the public authoring-surface API reference for LunaFlow, generated by
[`DefaultDocumentation`](https://github.com/Doraku/DefaultDocumentation) (the `DefaultDocumentation.Console`
dotnet tool, pinned in `.config/dotnet-tools.json`) from the `/// <summary>` XML doc comments in
`src/`. It is the single source of truth for public type signatures — design/spec docs should link
here rather than restating them.

## Layout

One top-level folder per authoring-surface project, each mirroring that project's namespace/type
hierarchy as actual folders (not dotted-into-a-filename, to stay well clear of Windows' 260-character
path limit):

```
LunaFlow.Rules/
  index.md                                  ← assembly overview
  LunaFlow/Rules/
    index.md                                ← namespace overview
    ARule/
      index.md                              ← type overview
      Reference.md, Superscedes.md          ← member pages
    GeneratorServices/
      index.md
      RulePipeline/
        index.md
        RulePipeline(IRuleParser,IRuleIRGenerator,IRuleCompiler).md
      ... (RuleExport, RuleIR, RuleCodeUnit, etc.)
```

Start at `<Project>/index.md` and drill down; every page links to its parent and children.

- `LunaFlow.Rules/` — the rule-authoring surface (`ARule`, `ILunaFlowReference`,
  `GeneratorServices` attributes/`RulePrototype`/`RuleExport`, etc.)
- `LunaFlow.Rom/` — ROM/content types (currently the Nine Rooms example content)
- `LunaFlow.Engine/` — scoped to just `LunaFlowEngine` (the content-facing entry point),
  `IEngineHost`, and `RuleEngine` — the actual content-authoring surface, per
  [handoff ticket 0014](../ClaudeWiki/Processes/Handoffs/0014-engine-api-surface-scope.md). Host
  console-wiring (`ConsoleEngine`, `DefaultCommand*`, `ICommand*`) and the host-implementer surface
  (`IGameEngine`, `IGameEngineTranslator`) are deliberately excluded via
  `src/LunaFlow.Engine/DefaultDocumentation.json` — neither is something content code touches.
  **Maintenance note:** that scoping is a deny-list (`Markdown.Exclude`), not an allowlist —
  `DefaultDocumentation` doesn't offer an include-list. A new public type added to
  `LunaFlow.Engine` appears in this reference by default; if it's host-wiring rather than
  content-facing, add a matching exclude pattern to `DefaultDocumentation.json`, don't assume it's
  covered. *(Noted 2026-07-19, ticket 0014 close-out.)*

Every public member is included (`--IncludeUndocumentedItems`), documented or not — nothing's
silently dropped for lacking a comment. As of 2026-07-19 every public member across all three
projects does have one.

The subfolders themselves are gitignored — they regenerate locally on every build. Only this
README is tracked in git; it stays visible in Solution Explorer via the default item glob in
`Documents/Documents.csproj`.
