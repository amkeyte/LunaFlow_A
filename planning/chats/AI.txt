# 🎮 GM Assistant System – Multi-Pass AI Reasoning

This document describes the internal architecture of the GM assistant’s multi-pass AI reasoning workflow.

```text
┌──────────────────────────────────────────┐
│              GM Input Console            │
│        ("Billie jumps into the lava")    │
└──────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────┐
│           Scene Context Builder          │
│  (Summarizes current location, actors,   │
│   recent events from GM scene notes)     │
└──────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────┐
│             Prompt Composer              │
│  (Formats LLM prompt with GM input +     │
│  context, asks: "What info do you need?")│
└──────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────┐
│         AI Pass 1: Query Analyzer        │
│  (LLM replies with structured list of    │
│   needed facts: character, rules, etc.)  │
└──────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────┐
│              Fact Resolver               │
│  (Pulls requested data from game state:  │
│   character sheet, rulebook, environment)│
└──────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────┐
│        AI Pass 2: Response Generator     │
│  (LLM generates Lua, narration, or logic │
│   using GM input + resolved facts)       │
└──────────────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────┐
│         Suggestion Display Engine        │
│   (Shows result to GM: accept/edit/run)  │
└──────────────────────────────────────────┘

##🔁 Optional Caching Layers
Scene Notes Memory → feeds into Scene Context Builder

-Used Facts Log → available for trace/debug

-LLM Model Adapter → backend interface (Ollama, OpenAI, etc.)

##✅ Design Goals
This modular pipeline ensures the assistant is:

-Traceable – each step is logged and inspectable

-GM-friendly – GM can preview or override every step

-Modular – each stage can be tested or swapped independently
