## 🧩 Rule Class Hierarchy (Example)

```csharp
public abstract class RuleBase { /* core runtime logic */ }

public abstract class BalancedRule : RuleBase
{
    public abstract bool IsFair();
    public abstract string[] ApplicableScopes { get; }
}

public class PlayerRule : BalancedRule
{
    public string CreatorId { get; set; }
    public bool IsCosmeticOnly { get; set; }

    public override bool IsFair() => IsCosmeticOnly || /* runtime limits */;
    public override string[] ApplicableScopes => new[] { "self", "pet", "emote" };
}
```

## 🎯 Example Responsibilities by Role

### 🔹 Player

* Adds cosmetic rules (e.g., `"when I enter town, a trumpet plays"`).
* Limited crafting or emote extensions (`PlayerRule`).
* Cannot access combat, world structure, or balance-relevant facts.
* Makes game requests and sends inputs: roll dice, get description, give character instructions

### 🔹 GM

* Toggles `"Goblin 3 is unkillable"` before or during a session.
* Launches cutscene script `start_throne_room_scene.lua`.
* Live-edit variables: `SetWeather("rain");` or `SetSpawn("none")`.
* AI assistance

### 🔹 World-Builder

* Adds `"GoldenDragon"` to `MonsterRegistry`.
* Defines `"SkyPillar"` region with environmental hazards and lore triggers.
* Uses script: `OnEnter(SkyPillar) => Play("cutscene_intro.sky_pillar")`.

### 🔹 Rulebook Author

* Expands `Player` with `Spellbook`, `Stamina`, and `Faction` traits.
* Implements `CombatPhaseManager`, `InventorySystem`, and `BalancedRule` constraints.
* Instantiates `Monster.Dragon` as a class backing mod-defined `GoldenDragon`.

### 🔹 Developer

* Provides core infrastructure: `RuleSession`, `ScriptRunner`, `LogView`, etc.
* Maintains `IRuleSource`, `IRuleValidator`, and hot-reload mechanisms.
* Enables extensibility via metadata (e.g., `IRuleDescriptor`, `IRuleTypeConstraint`)
